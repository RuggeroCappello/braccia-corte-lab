# Come consegnare il tuo lavoro

[Torna alla pagina iniziale](../README.md)

## Percorso semplice: senza account GitHub

1. Rinomina la cartella esperimenti con un codice di gruppo, per esempio `braccia-corte-gruppo-07`.
2. Aggiungi la tua scheda compilata. Non includere password, chiavi API o conversazioni personali.
3. Comprimi **tutta la cartella**: su Windows tasto destro → Comprimi in file ZIP (oppure Invia a → Cartella compressa); su Mac tasto destro → Comprimi.
4. Consegna lo ZIP tramite il canale indicato dal docente. Non viene inviato automaticamente.
5. Prima di consegnare, estrai il tuo ZIP in una cartella nuova, apri `index.html` e controlla che funzioni. Così scopri se hai dimenticato un file.

Consegna anche un’indagine rimasta aperta: scrivi cosa hai provato e qual è il prossimo passo sensato.

## Percorso facoltativo: GitHub

Fallo solo se il docente ha previsto gli account e la pubblicazione. Il progetto è pubblico: anche segnalazioni e proposte pubblicate qui saranno visibili.

- Una **issue** è una segnalazione o una domanda. Nella pagina del progetto apri **Issues → New issue**, scegli la scheda e descrivi il comportamento. Non occorre scrivere codice per fare una buona segnalazione.
- Un **fork** è una copia del repository nel tuo account. Dalla pagina del progetto premi **Fork**, poi **Create fork**. Ora lavori nella tua copia, non in quella della classe.
- Per una piccola modifica, nel tuo fork apri il file, premi la matita, applica la modifica già provata e scegli **Commit changes**: un commit è un salvataggio con una descrizione. Scrivi cosa hai cambiato.
- Per caricare i file modificati sul computer, usa **Add file → Upload files** dentro il tuo fork. Rispetta le cartelle originali; non caricare uno ZIP al posto dei sorgenti, né l’intera cartella esterna come sottocartella.
- Scarica lo ZIP del tuo fork e provalo: cambiare un file su GitHub non aggiorna automaticamente quello sul computer.
- Una **pull request (PR)** è una proposta di modifica al progetto della classe. Nel fork usa **Contribute → Open pull request**, controlla il confronto e spiega problema, modifica e prove. Non è necessaria per la consegna semplice.

Se i pulsanti non compaiono, fermati e chiedi al docente. Non chiedere all’IA di pubblicare al posto tuo senza avere letto il contenuto.

## Mini-presentazione, 60 secondi

“Ho osservato …; pensavo …; l’IA ha suggerito …; ho controllato con …; il risultato è …”. Conta la qualità della prova, non il numero di righe cambiate.
